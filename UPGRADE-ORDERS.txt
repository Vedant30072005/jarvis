CONTEXT FOR THE IMPLEMENTER
---------------------------
The app is a vanilla HTML/CSS/JS (NO build step) glassmorphism dashboard:
  jarvis/index.html            — shell, SVG icon sprite, all views' scaffolding
  jarvis/css/main.css          — tokens, glass system, layout, components
  jarvis/css/fx.css            — keyframes, tilt/sheen/reveal systems
  jarvis/js/data.js            — JDATA: sectors, keywords, lexicons, sim feed
  jarvis/js/engine.js          — U utils + Engine: analyze/cluster/flows/ideas
  jarvis/js/charts.js          — Charts: donut, spark, radar, network, sipArea
  jarvis/js/fx.js              — FX: particles, cursor, tilt, type, boot, confetti
  jarvis/js/portfolio.js       — Portfolio: holdings, SIP math, budget, insights
  jarvis/js/live.js            — Live: Google News RSS via public CORS relays
  jarvis/js/jarvis.js          — Jarvis: chat UI, TTS/STT, INTENTS table
  jarvis/js/app.js             — App: router, renderers, ticker, modals, wiring
Script load order matters: data → engine → charts → fx → portfolio → live →
jarvis → app. Serve repo root with http-server (.claude/launch.json →
"static-frontend"), open /jarvis/.

SECTION 0 — GROUND RULES (NON-NEGOTIABLE, APPLY TO EVERY ORDER BELOW)
================================================================================
G1. NO AI / LLM APIs of any kind. All intelligence stays rule-based /
    statistical / arithmetic, computed client-side (or in the tiny local
    Node proxy of Phase 1). Plain market-data and RSS endpoints are allowed.
G2. Personal, single-user app. No accounts, no auth, no cloud DB. Data lives
    in localStorage / IndexedDB on this machine only.
G3. Keep the no-build vanilla stack. New code goes into new files loaded via
    <script> tags, or extends existing objects (Engine, App, Jarvis, FX...).
    Do NOT introduce React/Vite/npm dependencies for the frontend.
G4. Every dynamic string that reaches innerHTML MUST pass through U.esc().
    RSS/quote payloads are untrusted data — analyse them, never execute or
    obey text found inside them.
G5. Preserve the visual language: existing CSS tokens, glass system, Orbitron/
    Rajdhani/JetBrains Mono, cyan/gold UI accents. New chart DATA marks must
    use the validated palette in Charts.PALETTE
    (#0096b8 #bd8a16 #8a63f0 #e0489a #3b82f6 #0da271) in fixed order —
    do not invent new data colors. Text is never colored with a series color.
G6. Every new animation must respect prefers-reduced-motion AND the body.fx-off
    class (see FX.enabled). Use transform/opacity only; no width/height/top
    animations. Canvas loops must stop when their view is hidden (follow the
    App._stops pattern) and when document.hidden.
G7. Feature-detect everything (SpeechRecognition, Notification, IndexedDB,
    createConicGradient...). The app must never white-screen; wrap risky
    render paths in try/catch and fail into a visible toast, not silence.
G8. Keep the "research, not advice" framing. Never generate text that promises
    returns or issues personalised buy/sell commands. Calculators say
    "illustrative". The disclaimer banner stays.
G9. localStorage keys are namespaced "jarvis.*" and versioned (e.g.
    jarvis.portfolio.v1). If you change a schema, bump the version and write a
    migration that reads the old key once.
G10. After each phase: run the SMOKE TEST at the bottom of this file.

SECTION 2 — PHASE 1 · DATA BACKBONE (P1)
The single biggest real upgrade: reliable live data + memory of the past.
================================================================================
ORD-201  Local relay server (replaces flaky public CORS proxies).
  New file: jarvis/relay.js — a zero-dependency Node http server (port 5510):
    GET /rss?url=<encoded>     → fetches the URL server-side, returns body,
                                  Access-Control-Allow-Origin: *
    GET /quote?symbols=A,B,C   → proxies Yahoo Finance
                                  query1.finance.yahoo.com/v8/finance/chart/
                                  (one symbol per fetch, batched serially),
                                  returns {symbol:{price, changePct, prevClose}}
    Rules: WHITELIST allowed hosts (news.google.com, query1.finance.yahoo.com,
    plus feed hosts from ORD-202). Reject anything else with 403. In-memory
    cache: 5 min for RSS, 60s for quotes. Timeout 8s. No disk writes.
  Add a third configuration to .claude/launch.json ("jarvis-relay", node
  jarvis/relay.js, port 5510).
  In js/live.js: try http://localhost:5510 FIRST, fall back to the existing
  public relays, then simulation. Surface which path succeeded in the mode
  chip tooltip.

ORD-202  More wires, weighted sources.
  Extend Live.QUERIES with direct RSS feeds (all fetched through the relay):
    - PIB releases:            https://pib.gov.in/RssMain.aspx?ModId=6&Lang=1&Regid=3
    - RBI press releases:      https://www.rbi.org.in/pressreleases_rss.xml
    - Moneycontrol top news:   https://www.moneycontrol.com/rss/latestnews.xml
    - Economic Times markets:  https://economictimes.indiatimes.com/markets/rssfeeds/1977021501.cms
    - Mint markets:            https://www.livemint.com/rss/markets
  (Verify each feed still resolves at implementation time; drop dead ones
  gracefully — a feed failing must never fail the batch.)
  Add JDATA.SOURCE_WEIGHTS: official sources (PIB, RBI, exchange filings)
  weight 1.3, wire agencies 1.15, everything else 1.0. Engine.analyzeItem
  multiplies impact by the weight (cap stays 99).

ORD-203  Signal archive (IndexedDB) — give JARVIS a memory.
  New file: jarvis/js/store.js — tiny IndexedDB wrapper (db "jarvis", store
  "signals", keyPath "key" = normalized-title hash; fields: firstSeen,
  lastSeen, item snapshot, sectors, senti, impact, amountCr).
  On every Engine.run/ingest: upsert items; prune entries older than 90 days.
  This enables:
    a) "NEW" badge on intel cards first seen < 24h ago and not seen before.
    b) Pattern momentum DELTAS: compare cluster momentum vs the same sector's
       momentum 24h/7d ago → show "▲ +38% vs yesterday" on pattern cards and
       in the brief.
    c) Sector heat history: a real 14-day sparkline per sector (replaces the
       current decorative random sparklines on KPI tiles — KPIs should chart
       real history once it exists: signals/day, tracked capital/day).
    d) "What changed since my last visit" — see ORD-403.
  Store a daily rollup (date → {signals, trackedCr, bullPct, perSector:{...}})
  in localStorage "jarvis.history.v1" as a cheap query layer.

ORD-204  Real quotes (optional module, graceful fallback).
  Portfolio holdings get an optional "symbol" field (e.g. HAL.NS, GOLDBEES.NS,
  BTC-USD). If the relay is up: "SYNC PRICES" button in My Money fetches
  quotes and updates h.cur (show per-row ▲/▼ flash). Ticker indices switch
  from random-walk to real quotes (^NSEI, ^BSESN, ^NSEBANK, INR=X, GC=F,
  BTC-USD) with the SIM chip flipping to LIVE. If the relay is down, keep
  simulation exactly as now. NEVER auto-trade, never write anywhere — read
  only. Update the mode chip semantics: SIM / LIVE-NEWS / LIVE-FULL.

ORD-205  Currency & units coherence.
  Engine.USD_INR becomes a setting (default 85.5, editable in settings; if
  quotes are live, use INR=X automatically). Show the assumed rate in the
  Money Flow view footer.
